# Relax: оригинальные длинные музыкальные выпуски

Режим для спокойной фоновой музыки и вечернего отдыха. Первый выпуск — «Вечер у моря»: 120 минут, 1280×720, 16 fps, H.264 + стерео AAC. Это синтезированные инструменты и нарисованная программой сцена, а не запись живого джазового ансамбля или настоящего места.

## Сборка

Нужны Rust 1.99+, Python 3.11+ и FFmpeg/ffprobe с libx264 и AAC. Зависимости Python: numpy, scipy, Pillow. Платные API, нейросетевые модели, soundfont и библиотеки музыкальных записей не используются.

```bash
python3 -m venv .venv
.venv/bin/pip install -r scripts/relax/requirements.txt
cargo run --release -- relax --minutes 120 --seed 207 \
  --python .venv/bin/python --output data/relax/evening-by-the-sea.mp4
```

Либо без компиляции Rust, из корня checkout:

```bash
.venv/bin/python scripts/relax/create_relax.py --minutes 120 \
  --seed 207 --output data/relax/evening-by-the-sea.mp4
```

Для короткого пробника задайте `--minutes 1`. Допустимый диапазон — 1–480 минут; это диапазон CLI, не утверждение, что восьмичасовой файл уже собран и проверен. Для двухчасового мастер-аудио требуется примерно 1,3 GB; оставьте несколько GB свободного места для промежуточных файлов. Время сборки зависит от CPU. Существующий MP4 не перезаписывается.

На выходе:

| Файл | Содержимое |
|---|---|
| `evening-by-the-sea.mp4` | Полный выпуск для скачивания и ручной загрузки |
| `evening-by-the-sea.preview.mp4` | Первые 60 секунд |
| `evening-by-the-sea.poster.png` | Постер |
| `evening-by-the-sea.verification.json` | Хеши, длительность, кодеки, уровень пика, декодирование |
| `evening-by-the-sea.causal-graph.json` | Причины, состояния, области действия, время и ссылки на зависимости |
| `evening-by-the-sea.work/` | Мастер-аудио и промежуточная анимация |

Создаются новые гармонические фразы, voicing, паузы и мелодические решения. Пятиминутные главы меняют тональность и интенсивность; отдельные музыкальные принципы могут повторяться, но готовый часовой аудиофайл не копируется. Реальная визуальная анимация повторяет 90-секундный цикл. Для разных выпусков нужен собственный творческий замысел, аранжировка и сцена; смена seed сама по себе не делает новый выпуск ценным.

## Проверки и причинный журнал

Для ограниченного по размеру скачивания есть отдельная копия. Полный мастер сохраняется:

```bash
.venv/bin/python scripts/relax/compact.py \
  --source data/relax/evening-by-the-sea.mp4 \
  --output data/relax/evening-by-the-sea-compact.mp4
```

Она использует 4 fps и более низкий битрейт AAC, поэтому для загрузки в YouTube предпочтителен полный мастер. Компактная копия тоже декодируется полностью и получает собственные метаданные и продолжение исходного причинного журнала. Размер до 100 MiB — требование выбранного способа передачи, не предел Google Drive.

Пакет проверяет всю звуковую и видеодорожку декодированием, длительность и цифровой пик. Генератор музыки дополнительно измеряет LUFS, true peak, отсутствие clipping и границы блоков. Граф хранит отдельные зависимости музыки и изображения от замысла и обе зависимости сборки; порядок записи не подменяет причинность. Rust CLI проверяет хеши событий и родителей через тот же `graph::verify`, который используется студией.

Это отдельный файловый процесс. Проект и очередь в веб-интерфейсе пока не создаются, доходы и публикации в экономику студии не записываются. Журнал описывает наблюдаемые действия создания файлов; наличие хешей не доказывает художественное качество или коммерческий успех.

## Права и YouTube

Код распространяется под MIT проекта. Музыка, реверб и иллюстрация синтезированы этим кодом без чужих записей, картинок, семплов, известных мелодий и стоковых шрифтов. Никакие исключительные права, принятие Content ID или одобрение монетизации автоматически не подтверждаются. Файлы не заявляют медицинского эффекта.

По [правилам монетизации YouTube](https://support.google.com/youtube/answer/1311392?hl=en) оригинальность оценивают по каналу целиком. Массовые однотипные шаблонные выпуски с минимальными вариациями могут не пройти проверку, даже если не нарушают copyright. Сохраняйте исходники и творческие решения, делайте существенно разные выпуски.

На 4 октября 2026 [порог рекламной монетизации длинных видео](https://support.google.com/youtube/answer/72851?hl=en) — 1 000 подписчиков и 4 000 квалифицированных часов за последние 12 месяцев, после чего проводится проверка канала. [Объявлено изменение](https://blog.youtube/news-and-events/youtube-partner-program-updates-2027-new-opportunities-earn/): с 1 февраля 2027 новым заявителям потребуется 8 000 часов за 365 дней; проверяйте текущие условия в YouTube Studio перед подачей.

Требуется проживание в [доступной стране YPP](https://support.google.com/youtube/answer/7101720?hl=en) и действующий AdSense for YouTube. Российские AdSense не могут монетизировать связанные каналы. Турция есть в списке YPP, но новая страна в настройках или VPN не подтверждают проживание и платёжный профиль. [Страну существующего AdSense не меняют](https://support.google.com/adsense/answer/2628816?hl=en): при реальном переезде Google описывает закрытие прежнего и создание нового аккаунта.

Если позже используется генеративная модель для основной музыки, проверьте [обязательное раскрытие AI use](https://support.google.com/youtube/answer/14328491?hl=en). Здесь используется процедурный синтез нот и тембров программой; это описание способа, а не решение YouTube о классификации конкретной загрузки.

Сначала прослушайте готовый выпуск. Затем вручную загрузите на свой выбранный канал и проверьте права/обработку в Studio. Эта команда не публикует ролики и не меняет настройки канала или AdSense.
